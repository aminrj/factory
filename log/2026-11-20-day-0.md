# Day 0: I'm building AI apps through a gated software factory, in public

I have a homelab that runs Kubernetes, an RTX 3090 serving local models, and coding agents that can write most of the code I need. What I didn't have was a habit of shipping small things to real people. Starting today, I'm fixing that in the open.

## What I'm doing

I'm building small AI apps for people I can name, through a software factory I run as a team of one. Agents write the code. I own the decisions.

The design follows the argument Dex Horthy made at AI Engineer World's Fair this year: fully automated "lights-off" factories fail because the damage shows up weeks after the tests go green. So I keep humans at the points where decisions are still cheap to change:

1. **Product:** the problem, the named user, and acceptance tests the agent never sees.
2. **Threat model:** every AI and web risk, and the control in code that handles it.
3. **Plan:** types, signatures and vertical slices, reviewed before any code exists.
4. **Slices:** one phase per agent session, checks between phases.
5. **Review:** I read the diff. CI runs secret scanning, SAST, dependency scanning, and two guards: agents cannot touch the acceptance tests, and any new test must fail against the old code.

My background is security and formal verification, so each gate is also a security control point. That is the part I want to measure.

## What I'll publish

- **The board:** every idea, its named user, its timebox, and whether it shipped or got killed. <!-- BOARD_URL -->
- **The template:** [aminrj/factory-template](https://github.com/aminrj/factory-template), the repo every app starts from.
- **The trail:** each app's spec, threat model and plan sit in its repo under `thoughts/`.
- **The numbers:** every pull request records my minutes per gate. A weekly job collects them into [data/SUMMARY.md](https://github.com/aminrj/factory/blob/main/data/SUMMARY.md): human minutes by gate, rework rate, how often the agent passes the hidden tests on the first try, and bugs found after merge.

## The rules

1. No real user, no build.
2. Hard timeboxes: 8 hours for a small app, 16 for a medium one. When time runs out, I ship or kill.
3. Shipped means someone other than me used it.
4. Killed apps stay on the board.

## App #1: brevkoll

Swedish letters from school and authorities cost international parents real time, and deadlines get missed. brevkoll takes a photo of a letter and returns a plain-language summary, what you need to do, and the dates as a calendar file. Nothing is stored.

The security story is the design. Letters carry personnummer and children's data, so OCR runs locally, identifiers are redacted before any model call, deadlines are parsed by code rather than trusted to a model, and the hidden acceptance tests check all of it. The first users are my own household, then parents at my kids' school.

I'll post the ship note with the numbers when it's live.
